## Product identity

**Brain Guardian OS** — a public, multi-tenant AI caregiving platform.

The earlier working name **br(AI)n App** came from the Google AI Studio prototype/build flow and may still appear in legacy folders, comments, or imported docs. **Brain Guardian OS** is the current product name. Do not use br(AI)n App as the product name in new code, schema, prompts, or harness files.

Roles: **admin** (caregiver who operates the system), **caregiver** (secondary care team), **patient** (care recipient). Never hardcode personal names into schema defaults, route handlers, seeds, prompts, or platform docs.

`care_events` is an **append-only evidence ledger** (audit trail). It is not a blockchain, not a crypto ledger, and not a reversible log. Every row must include `tenant_id` derived from the active session — never from a client-supplied field, never `"local"` as a fallback.

## Non-negotiable rules for all agents

1. **One active writer at a time.** Before editing: `git pull --rebase`. After: commit and push. Never edit on two machines or with two agents simultaneously — this rule applies across all tools (Claude, Codex, Cursor, Gemini, poolside, etc.), not just this repo.
2. **Proof block before any session:**
   ```
   pwd
   git rev-parse --show-toplevel
   git branch --show-current
   git remote -v
   git status --short
   ```
   If any of these look wrong, stop and report. Do not edit.
3. **No broad rewrites.** Propose changes, wait for approval. Targeted fixes only unless explicitly told otherwise.
4. **Open the repo root** — not a subfolder (`artifacts/brain-app`, `artifacts/api-server`, etc.).
5. **care_events rows must include `tenant_id`** derived from the session, never client-supplied, never `"local"` as a fallback.
6. **Doctor files and clinical summaries must source from verified `care_events`** — not loose AI-generated text passed off as clinical records.
7. **CORS is exact-match.** No `startsWith`, no wildcards.
8. **Generated files are never hand-edited.** `lib/api-client-react/src/generated/` and `lib/api-zod/src/generated/` are regenerated by codegen only.
9. **`import { z } from "zod/v4"`** — not `"zod"`.
10. **Canonical remote:** `https://github.com/shadowsys-memphis/Guardian.git` — HTTPS only. Do not use `LEDGERGHOST90` for this repo.
11. **Destructive operations require an approved plan.** No agent may merge, rebase, push, force-push, delete branches, delete files, or rewrite history without first presenting a written plan and receiving explicit approval in that session. Read-only analysis (git diff, git log, file inspection) is always allowed. If in doubt whether an operation is destructive, treat it as destructive and ask.

## Model routing / cost discipline

Applies to every agent in the Hermes/OpenClaw/Gemini/Codex/Claude world. Full workflow: [`.claude/skills/spec-first-routing/SKILL.md`](.claude/skills/spec-first-routing/SKILL.md).

- **Separate command from labor.** A strong/frontier model (Claude, Fable, GPT-5.5-class) plans, writes the spec, and reviews the diff. A cheaper model (Codex, Gemini CLI, Haiku-class) writes the bulk code and applies fixes.
- **The spec is the handoff contract.** Never send a builder model into this repo without a locked, written spec (files touched, exact signatures/routes, edge cases, acceptance criteria). The spec is what stops every model from rediscovering the whole architecture on every task.
- **Never let the cheap model make architecture decisions.** If a builder hits an ambiguity the spec doesn't cover, it stops and escalates back to the architect — it does not guess.
- **Never merge without a strong-model review of the diff.** The reviewer checks the diff against the spec *and* against this file's non-negotiable rules (tenant scoping, CORS, zod/v4, generated files, etc.) before anything ships.
- **Route by task, not by habit.** Trivial one-line fixes, auth/tenant-scoping/billing code, and genuinely ambiguous/exploratory work stay with the strong model — writing a spec for those costs more than it saves.

## Branch discipline

- `master` — stable, always deployable
- Feature/pass branches (e.g. `mobile-admin-pwa-pass`) — one machine owns the branch at a time
- Never force-push `master`
- Always fast-forward merge or rebase — no merge commits into master without approval
